The goal & what was built

The whole project is the migration: re-implement RocksDB as a pure-Zig 0.16 LSM key-value engine, built bottom-up under strict TDD, and finish by making byte-exact RocksDB the only on-disk format zrocks emits — proven by having a real librocksdb v11.4.0 binary open zrocks's flush, compaction, range-delete and WAL output through a verify_open oracle.

The result is a working, durable, crash-recoverable, leveled-compacting LSM store with a CLI: foundation (slice/status/coding/comparator/arena/CRC32C/options) → Env over std.Io → WAL · skiplist · memtable · WriteBatch → block-based SST (builder/reader, bloom, footer) → LRU cache → iterators → VersionEdit/VersionSet/MANIFEST → recovery → flush + leveled/universal/FIFO compaction → snapshots → column families, merge operator, prefix seek, compaction filter, range delete, transactions, checkpoints → then the format migration to byte-exact RocksDB.

What the failures actually were

  • StructuredOutput (40, the biggest bucket) — workflow agents whose first JSON didn't satisfy the required schema, e.g. must have required property 'verdict_note' / 'already_rocksdb_exact'. These are self-correcting retries: the harness rejects the output and the agent re-emits a valid object. No work was lost; they inflate the count without being real failures.
  • EnterWorktree (4, 100%) — a subagent tried to call EnterWorktree while already running with a cwd/worktree override: "cannot be called from a subagent with a cwd override." A harness guardrail, not a code bug; the orchestrator owns worktree creation.
  • Bash (65, ~2%) — dominated by expected failures: zig build test exiting non-zero on the red step of red→green TDD, plus a handful of cat on a not-yet-existing MEMORY.md and two transient "claude-opus-4-7 is temporarily unavailable" auto-permission stalls.
  • Edit (15, ~1.4%) — "File has been modified since read… Read it again" and "Found 2 matches… set replace_all." Standard edit-contract hiccups, immediately retried.
  • Read / Write (3) — one EISDIR (read a directory as a file), one missing file, one write-before-read. All recovered on the next call.
Reading the rate: of 128 errors, the large majority are designed-in — TDD red builds, schema-validation retries, and a harness guardrail. Subtracting those, genuine unexpected tool failures (stale edits, wrong path, EISDIR, transient model unavailability) number roughly ~25, i.e. well under 0.5% of all tool calls. The agent recovered from every one without losing milestone progress. Part II reports the migration phase's own failure ledger: 0 subagent retries.

Failure analysis (migration)

The migration completed with 0 retries and 0 quarantined milestones. Every one of the 28 subagents finished on its first attempt; every one of the 9 execute milestones merged to main. The execute workflow’s pre-commit gate (full zig build test + the real-RocksDB verify_open oracle) was the safety net that made retries unnecessary — an agent that broke the gate would have been quarantined and its dependents skipped, but none did.

EventWhereOutcome
Latent bug discovered mid-flight Milestone 4 (manifest-rocksdb-exact) Fixed in-band. Before the migration, compaction.zig:commitCompaction emitted compaction outputs via addFile (legacy kNewFile=7, no seqnos). This wasn’t caught earlier because no test exercised compaction after a multi-level fill. The milestone’s red test surfaced it; the same milestone’s green commit (4d0f04b) fixed it by switching to addFile4 with real min/max seqnos.
Oracle count regression at milestone 6 range-del-rocksdb (OPEN_OK 5) Expected. The narrower fixture used by intermediate gates only carries 5 live non-tombstoned keys; the gate’s contract is “real RocksDB opens it,” not a fixed count. The next milestone’s richer fixture lifted it back to 11, and the final milestone’s end-to-end DB hit 34.
2x TaskStop in subagent traces Execute phase (long-running background zig build jobs) Cooperative. Both were agent-initiated stops of own background zig build test jobs after a faster path produced the answer — no test was abandoned.
Subagent retries — 0 / 28 — every agent reported attempt=1, state=done.

What the migration deleted

  • Options.sst_output enum + field (forced single output format)
  • Native single-level SST index path (write side)
  • Two-level partitioned SST index (src/format/partitioned_index.zig, 373 LoC + 3 tests + Options.IndexType)
  • Block-based-bloom write path (read path retained for LevelDB interop)
  • Bespoke range-tombstone serialization (replaced by rocksdb.range_del)
  • kColumnFamilyTag=0x10 WAL prefix (replaced by RocksDB CF value-type bytes)
  • Per-CF MANIFEST snapshot path emitting legacy kNewFile=7
